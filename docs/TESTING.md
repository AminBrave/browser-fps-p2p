# Testing\n\nThis project uses Node's built-in test runner so the simulation and networking core can be tested without a browser.\n\n## Commands\n\n    npm test\n    npm run test:coverage\n    npm run test:watch\n\n## Test layers\n\n- `test/simulation/` — deterministic movement rules.\n- `test/combat/` — damage, health, weapon state, projectile direction, impact seeds, shot events, and ballistic tracing.\n- `test/network/` — packet serialization, validation, snapshot timelines, world manifests, client prediction/reconciliation, interpolation, and authoritative host input handling.\n- `test/physics/` — injected physics boundaries and spawn safety.\n- `test/utils/` — bit flags, replay buffers, and accuracy calculations.\n- `test/config/` — configuration validation, deterministic peer IDs, ECS component factories, and deterministic map placement.\n- `test/integration/` — cross-module determinism invariants.\n\n## Best-practice rules\n\n1. Keep simulation tests deterministic. Inject random-number generators instead of relying on `Math.random()`.\n2. Test network packets as byte-level contracts through encode/decode round trips and malformed-packet cases.\n3. Test client prediction and reconciliation separately from rendering.\n4. Test stale sequence/tick rejection explicitly because packet reordering and duplication are normal network conditions.\n5. Keep Three.js, DOM, WebRTC, and Rapier integration tests separate from unit tests. Use dependency injection and small fakes for unit coverage.\n6. Never make tests depend on real wall-clock timing when a deterministic timestamp can be supplied.\n7. Every regression bug should gain a test that would have failed before the fix.\n\nThe GitHub Actions workflow in `.github/workflows/unit-tests.yml` runs the test suite and coverage check for pushes and pull requests targeting `architecture-overhaul`.\n
